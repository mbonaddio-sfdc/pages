For the tester

Read this first

You are the independent beta tester for a Salesforce accelerator called Agent Governor. It is a lightweight "traffic controller" for an Agentforce / MIAW chat agent: a small server-side API returns GO or STOP for a given agent, and a JavaScript wrapper on the web page decides whether to show the agent based on that answer. It gives an admin four safety controls — a master kill switch, a daily conversation cap, operating hours, and a % traffic sampling dial.

Your job is not to be told how to install it. Your job is to install it from the published docs alone, exactly as a real adopter would, and tell us where you got stuck and whether each control actually works.

Ground rules (this is what makes it a valid test)

  1. Docs only. For the install (Part A) use only the repo's README.md. Do not ask the author for help, and do not use this packet as an install guide — this packet only tells you what to verify, not how to install. If the README doesn't tell you how to do something, that is a finding: write it in the friction log and do your best to proceed.
  2. Log everything that isn't obvious. Every unclear step, missing detail, error message, or "I had to guess" moment goes in the feedback form's friction log, with the README section it relates to. Friction is the most valuable thing you produce.
  3. Time-box it. Aim for ~60–90 minutes total. If you're blocked for more than ~15 minutes on one step, log it as a blocker and move on to whatever you can still test.
  4. Additive only / it's a real org. The target is a live demo org, not a throwaway. Only add things (the deploy, one config record, one Site). Don't delete or modify existing metadata. A clean tear-down is Part D.

Part C — Functional tests (do the four controls actually work?)

The tests come in two layers:

  • Layer 1 — the server decision (no wrapper, no CORS). Paste the endpoint URL straight into your browser address bar and read the raw JSON. This proves the server-side logic deterministically.
  • Layer 2 — the wrapper on a page (the real integration). Use the hosted test page to confirm the JavaScript actually shows / hides the agent based on that decision, including the client-side sampling dial and the fail-safe.

Your endpoint URL

Take your Site base URL (from Part A / README) and append the API path:

https://<YOUR-SITE-BASE>/services/apexrest/AgentGovernor/?key=beta-test

Open that URL in the browser. You should get a small JSON object like {"status":"GO","reason":"OK","samplingRate":1.0}. If you get an error page instead, the Site or guest-access setup (A7) isn't right — log it; that's a finding.

Tip: the endpoint caches nothing, but your browser might. After changing the config record, hard-refresh (Ctrl/Cmd-Shift-R) or add &t=<random> to the URL.

Optional C4-full — daily limit end-to-end (only if your demo org has a working agent)

The read-path test proves the response. To prove the counter actually increments:

  1. Set Daily Limit = 1, Current Count = 0, Is Green = true, Reset Date = today, and make sure Linked Channel Id points at your demo agent's MessagingChannel.
  2. Start one real conversation with that agent (send at least one message so a MessagingSession is created).
  3. Reload the endpoint URL. Expect STOP / QUOTA, and on the config record confirm Current Count = 1 and Is Green = false. (The count updates asynchronously — give it a few seconds and refresh.)

Layer 2 — the wrapper on a page

This proves the client actually shows/hides the agent, plus the sampling dial and the fail-safe. Open the test page — think of it as a stand-in for a customer's website with the wrapper installed. It shows a Decision panel and a placeholder agent bubble (bottom-right) that appears only when the wrapper would actually launch the agent — i.e. Decision = GO and you were sampled in.

One-time setup (CORS)

The page runs in your browser and calls your Salesforce Site. The browser blocks that call unless the Site trusts the page's address. Add it once:

  1. In the demo org: Setup → Quick Find CORS → CORS → New.
  2. Origin URL Pattern: https://mbonaddio-sfdc.github.io (origin only — no /pages/, no filename, no trailing slash). Save.

If the page shows a red ERROR with "Failed to fetch", the two usual causes are: this CORS entry is missing, or the Site base URL you typed is wrong.

Sampling is "sticky" for your browser session, on purpose. The first Run check rolls the dice once against the Sampling Rate and then remembers the in/out result for the session (so a live visitor doesn't see the agent flicker). Practical consequence: if you change Sampling Rate in Salesforce, click Reset session sampling before Run check to force a fresh roll.

The test loop for every control below is the same: change the field on your config record → Save → back to the page → Run check. Record the result in the feedback form and tick it here.

Exact number formatting may vary slightly by browser (1.0 vs 1); what matters is the status and reason pair.
